CRCI Architecture

Local misbehaving-peer isolation · v2.1.0 · how the code is wired today, including known gaps

Crates

  • • crates/crci-core — protocol library (lib + cdylib), HTTP API, UniFFI exports, simulation code
  • • crates/crci-node — crci-node CLI, helper binaries, integration tests, benchmark harnesses
  • • bindings/kotlin/generate.sh — regenerates the Android Kotlin bindings

Clients

  • • web/dashboard — React + Vite, reads one node's HTTP/WS API
  • • crci-android — Compose demo app, in-process node via UniFFI, no networking
  • • Dockerfile + docker-compose.yml — 2 honest nodes, 1 adversary, dashboard

Where the paper's mechanism lives

  • • Strikes, bans and the replay filter run in NodeRuntime for every message, TCP included
  • • All paper benchmarks drive NodeRuntime in-process (docs/benchmarks.md)
  • • On TCP strikes bind to the key a neighbour proved in the handshake
